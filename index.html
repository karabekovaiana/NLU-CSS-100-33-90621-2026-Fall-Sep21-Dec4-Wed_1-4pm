Corporate Handbook

Company Culture & Operations (Syllabus)

Review our operational guidelines. This document outlines our mission, what is expected of you, and how your performance will be evaluated during your tenure at CSS:100 Inc.

Corporate Mission (Course Description)

To bridge the critical gap between raw computational problem-solving and effective, human-readable communication. In the modern tech landscape, writing brilliant code is only half the job; the other half is explaining, documenting, and collaborating on that code. This simulation provides a hands-on environment for mastering both.

Core Competencies (Objectives)

  • Master fundamental Git & GitHub workflows (Commits, Push, Pull Requests).
  • Develop basic proficiency in HTML/CSS and DOM structures.
  • Produce clear, professional technical documentation and commit messages.
  • Understand logic structures and algorithmic problem-solving.
  • Navigate corporate-style codebases safely without causing regressions.

Performance Metrics (Grading)

Sprint Deliverables (Assignments) 40%
Quarterly Review (Midterm Project) 25%
Final Deployment (Final Project) 25%
Stand-ups (Attendance & Participation) 10%

Office Protocols (Policies)

Deadlines (Sprint Cycles) Pull requests are strictly due by the end of the sprint cycle. Late commits will be flagged in the system and subject to penalty.
Collaboration vs. Plagiarism Pair programming is encouraged! However, directly copying another engineer's code without citation or understanding violates our corporate integrity policy.
AI Assistance Tools Use of AI (like Copilot or ChatGPT) is permitted for syntax debugging, but you must be able to fully explain and defend any code you commit during code reviews.
Internal Mobility

Career Progression at CSS:100

Your initial pull request gets you in the door as an Entry-Level Engineer. As the semester progresses and your skills level up, you will earn hypothetical promotions based on your performance grades, requiring further code commits to update your corporate status.

Level 1

Entry Level

Completed Onboarding PR.

Level 2

Junior Engineer

Mastering the basics of their chosen track.

Level 3

Senior Engineer

Consistently delivering high-quality work.

Level 4

Manager

Leading peer reviews and technical documentation.

Level 5

VP / C-Suite

Top performers in Cyber, Web, or Data tracks.

The Promotion Protocol

When you receive a grade that qualifies you for a promotion, your next task is to submit a new Pull Request. You will edit your HTML Employee Card in the directory below, changing your Rank (e.g., from Entry to Junior) and specializing your Track (e.g., Web Developer, Cybersecurity Analyst). This reinforces continuous Git workflows and HTML DOM navigation.

Employee Orientation

Onboarding Task: Company Directory Drop

Your first ticket as a new hire is to generate your employee ID badge and append it to our company directory.

1

Fork & Clone Company Repo

Fork the official CSS:100 Inc. repository to your own GitHub account, then clone it to your local workspace.

2

Locate the ID Badge Template

Open index.html in your editor. Scroll down to the Company Directory section. Locate the HTML comment that says <!-- STUDENT TEMPLATE START -->.

3

Edit and Embed Your Credentials

Uncomment the template, fill in your Name, Role/Major, a short Bio, and your GitHub URL. Do not break the surrounding HTML grid structure.

4

Commit with Context Technical Writing Focus

This is the most critical step of onboarding. When you commit your changes, you must write a descriptive commit message that explains what you did and why. Avoid unhelpful messages.

# BAD Commit Message

git commit -m "added my name"

# GOOD Commit Message (Use this format!)

git commit -m "feat(directory): append Jane Doe employee badge to index.html"


# Optional extended description (for PRs):

# "Cloned the onboarding template block and inserted my personal details, including intended major and github link, to complete New Hire Orientation."
